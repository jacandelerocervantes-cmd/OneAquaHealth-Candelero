## Guardrails and lessons this session re-learned or added (read before doing anything risky)

- **Never hardcode any absolute filesystem path, session-scratchpad path, or Windows account name
  anywhere under `src/`, `tests/`, `scripts/`, `docs/`, `AGENTS.md`, `README.md` or `.env.example`.**
  `tests/portability/test_no_absolute_paths.py` scans all of those, including `LEDGER.md` itself —
  this session both found a prior instance of this bug and then made it again in its own ledger
  text before catching and fixing it. If you need to reference a local dev venv, a GCP resource
  path, or any other machine-specific detail in a doc, describe it in words or point to the doc that
  explains how to find it (e.g. `docs/environment_setup.md`), never paste the literal path.
- **The project's own dev venv on this machine lives outside the repository, in a sibling/user-local
  folder** (see `docs/environment_setup.md` for the general pattern — do not hardcode the exact path
  in any repo file, per the rule above). It has all dependencies installed (`pytest`, `hypothesis`,
  `fastapi`, `ruff`, `mypy`, etc.) and is the correct interpreter to run the test suite with.
- **`gcloud compute instances delete` (and presumably other destructive infrastructure commands) can
  be refused by this session's own server-side safety classifier**, independent of the project's own
  git-commit guardrail. When that happens: stop (don't delete) instead if a non-destructive
  equivalent exists, and hand the destructive step to the user rather than trying another tool or
  path to work around the refusal.
- **A `pd-standard` (HDD) persistent disk on a small machine type can be extremely slow for a
  large sequential read-then-hash workload** — dominated by I/O latency, not bandwidth or CPU.
  Neither a bigger machine type nor a live disk-size increase (which only raises `pd-standard`'s
  bandwidth cap, not per-operation latency) meaningfully helped in this session. If this pattern
  recurs, try a `pd-ssd` disk or a tool that reads in larger buffers, before assuming more CPU or
  a bigger disk will fix it.
- AGENTS.md still requires every turn to start by reading `docs/handoff/LEDGER.md` and end with a
  complete entry there; this handoff file supplements, not replaces, that ledger.
