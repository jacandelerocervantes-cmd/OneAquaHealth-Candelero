## 1. Situation

OneAquaHealth is a hackathon project (IEEE OneAquaHealth Global Hackathon 2026): a pipeline that turns the public HL7
Europe OneAquaHealth FHIR sandbox into a trustworthy water-quality index, with explanations checked against the
evidence and a citizen-science reliability layer. It is a **demo version**, not a tool for regulatory use.

- **Deadline: 7 October 2026, fixed.** Today is 2 October. The maintainer's split of the remaining time: two days to
  build the web app, two days to test and record the video together, then the submission. There is no slack day, so
  the cut line in section 9 matters.
- **What the organisers require:** the track and how the project answers it; a project description (problem, solution,
  target users, expected impact on ecosystems and human health); a 3 to 5 minute demo video; a public code repository
  with source and documentation; a working prototype; Devpost registration before the deadline.
- **Judging:** impact and alignment with the mission 30%, innovation 20%, technical implementation 20%, usability and
  experience 15%, feasibility and scalability 15%. Rules: original and developed during the hackathon period; no
  copyright, licence or third-party IP violation.
- **Tools the maintainer uses:** Claude and CapCut (video). Remote Control may be on for the maintainer's tablet.
- **Still unknown:** the track chosen; the maintainer has not said.

## 3. Rules that bind every session (from `AGENTS.md` and the hooks)

- **Never run `git commit`** or change git configuration: the maintainer commits. A guard hook blocks commits, pushes
  and merges and blocks destructive shell commands. Staging with `git add` is fine. If a hook blocks something,
  do not work around it: explain and give the command.

  with the Write tool and run them, and never read or edit the environment file (the maintainer maintains it).

- Paths: only `src/oah/paths.py` builds project paths; no absolute paths or personal account names anywhere in the

## 3b. Credentials for testers

The maintainer wants shared e-mail and password pairs in a `.md`. `AGENTS.md` says credentials belong in the
non-versioned environment file, so decide this explicitly with the maintainer: (a) a **gitignored** file shared only in
the Devpost testing instructions (recommended), or (b) a versioned file containing only **disposable, low-privilege
accounts** (role: citizen), with passwords rotated after judging. Never put a reviewer or administrator credential, a
database key, the service key or the model key in any file. Generate the test accounts with a script run by the
maintainer (not by an agent typing secrets), and prefer closing open sign-up so that only the shared accounts exist.

## 5. Facts about the real data (public sandbox, read on 2026-09-29)

23 Locations; 12 are Benevento AIR-quality stations (not water); the only site with evaluable water data is
**Almyros (Crete, Greece)**, a river, which uses the Greek national limits; the Giofyros reaches only have water
temperature (not scored for Greek rivers); other river-typed sites (Strawberry Creek, a Coimbra site) have no
instrument. 141 population-health Observations exist for Oslo (81) and Benevento (60), all aggregated percentages
by group. The macroinvertebrate indices are not computed on real data because the sandbox has no count records.
So the honest story is trust and method, with Almyros as the hero site. BMWP and ASPT need a regional tolerance
table that the repository does not ship (diversity indices need none).
